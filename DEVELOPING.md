# Developing SEL Trip Event Analyzer

Everything lives in one file, `sel_trip_analyzer.py`: parsers, cause analysis,
review flags, report and Word/PDF export, the updater, and the Tkinter GUI.

## Run from source

```
pip install -r requirements.txt
python sel_trip_analyzer.py
```

When run from source, the updater replaces the `.py` file with the release's
version instead of the `.exe`.

Command line (no window):

```
python sel_trip_analyzer.py --cli <files or folders> [--comments "text"] [--out report.docx] [--out report.pdf]
```

This prints the report and writes any `--out` files (`.docx`, `.pdf` or `.txt`).

## Tests

```
python -m unittest discover -s tests -v
```

The tests cover parsing for every file type, cause analysis, every review flag,
Word/PDF export and the updater. They run on every push (`.github/workflows/tests.yml`),
and each release also test-drives the built `.exe`.

The expected answers come from the sample files. To lock in behaviour on
**real** relay files, add a scrubbed case under `tests/fixtures/` (see the
README there). This repo is public, so replace relay and station names first.

## Sample files

`sample_files/` is generated by `python scripts/make_samples.py`. That script
also writes `SEL_sample_files.zip`, which the release workflow attaches to each
release. To change a scenario, edit the script and regenerate; don't hand-edit
the files. The `.rdb` is a real OLE compound file, written by a minimal writer
in the script.

## Browser version

`web/core.js` is a line-for-line JavaScript port of the parsing and analysis in
`sel_trip_analyzer.py`, and `web/app.html` is the page. `python scripts/build_html.py`
inlines both, the sample files and the icon into one file,
`dist/SEL_Trip_Analyzer.html`, with no outside dependencies.

**Keep the two versions in step.** When you change parsing or analysis in the
Python file, make the same change in `web/core.js`. `tests/test_web_parity.py`
runs both on the sample files and a set of edge cases, and fails on any
difference in the report. `node web/cli.js <files>` runs the browser core from
the command line.

`tests/browser_test.js` drives the built page in Chromium (Playwright): samples,
upload, folder upload, edits, Word/text/print export, feedback, the update
banner, dark mode, help and the phone layout. CI runs it on every push.

The online copy is served by GitHub Pages from the `gh-pages` branch
(Settings → Pages → Source: **Deploy from a branch**, `gh-pages`, `/ (root)`).
`.github/workflows/pages.yml` rebuilds the page and updates that branch whenever
the app changes on `main`; don't edit `gh-pages` by hand.

## Building the .exe

On Windows, double-click `build_exe.bat`. The output is `dist\SEL_Trip_Analyzer.exe`.

## Releasing

1. Bump `VERSION` in `sel_trip_analyzer.py` and merge to `main`.
2. On GitHub: **Releases → Draft a new release**, create tag `vX.Y.Z`
   (matching `VERSION`), write what changed, and publish. Users see these
   notes in the update prompt.
3. `.github/workflows/release.yml` builds the `.exe` on Windows, runs the
   tests, smoke-tests the `.exe` (parse + Word/PDF export), and attaches
   `SEL_Trip_Analyzer.exe`, `SEL_Trip_Analyzer.html` and `SEL_sample_files.zip`
   to the release.
   Installed copies then offer the update.

The workflow can also be run by hand (**Actions → Build and release → Run
workflow**) to trial-build a branch without publishing anything.

## Screenshots and icon

- `.github/workflows/screenshots.yml` renders the app on a Windows runner and
  commits `docs/screenshots/*.png` whenever the app or the screenshot script
  changes on `main`. The script is `scripts/screenshots.py`; the screenshots
  are in dark mode.
- The icon is drawn by `scripts/make_icon.py` and saved to `assets/`.

## How the analysis works

1. **Parse.** Each file becomes `EventRecord`s. CEV files supply analog samples
   (currents and voltages are estimated from quarter-cycle-spaced samples) and
   relay word bits (the element timeline, TRIP and breaker 52A). Text reports
   supply the event type, targets, location and currents. RDB files supply
   settings, matched to events by RID.
2. **Analyze** (`analyze_event`). It works out the trip, the primary element
   (from TR/TRCOMM/TRSOTF/DTT hits before the trip, or else the elements that
   asserted with the trip), and the clearing time. It produces `checks` (things
   that look wrong or ambiguous, which lower confidence) and `gaps` (missing
   data). Both appear as `CHECK:` lines.
3. **Report** (`build_report`). Events are sorted by time, history rows are
   linked to matching detailed reports, and the result is plain text. Word and
   PDF export re-parse that text (`parse_report_text`), so user edits carry
   through.
